# Honest-reporting fixes: money dedup, buyer-tracking perturbation, four-cause inconclusive split, hazard-dodge reclassification (v1)

Five commits on `main` above `a51d733` correct four reporting bugs where AgentProof's own output — the product — lied about what a run proved. Money-at-risk was summed once per firing rule, so one order objected to by two invariants counted twice; state-perturbation faults hit a hardcoded arabica shelf regardless of what the agent bought, so live journeys "passed" a rule they never exercised; the inconclusive footnote merged "the agent never reached the fault" with "the merchant refused the fault" into one cause; and agent-driven journeys that dodged their own hazard were reported as clean passes counting toward READY. Each fix ships a test that bites on revert, HamperHub's frozen demo numbers are byte-identical, and money stays in integer minor units.

Watch for: (1) **confirmed** — the deterministic reg-07/reg-08 reproductions now depend on the *quote line-item order* landing arabica first rather than naming it directly; the coupling is implicit and only holds because `create_quote` preserves bundle order. (2) **possible** — `sumMoneyAtRiskByOrder` falls back to the content-derived violation id when both `intentId` and `quoteId` are empty, so two null-intent violations on the genuinely same order would each count once; verify money-bearing violations always carry an intentId. (3) **confirmed** — `fault_rejected_by_merchant` is assigned whenever `apply()` throws after the trigger was reached, which includes the "no product in the order to perturb" throw, not only genuine merchant refusal.

**Verdict**: APPROVED

## High-level view

The money fix groups violations by order (intentId, then quoteId, then the content id) and takes the MAX within each group before summing across groups. MAX is right because every rule objecting to one order carries that order's value, so max equals the value and stays robust if amounts ever diverge. Verified live: `reg-04-expired-quote` fires both INV-INVENTORY and INV-QUOTE-EXPIRY on one ₹1399 checkout and now reports ₹1399, not ₹2798.

The perturbation fix inverts `contestedProduct` to prefer the buyer's most-recent quote line item, with the named product as a fallback. For the deterministic suite this still resolves to arabica because the scripted HAMPER bundle lists it first and the quote preserves that order — a working but implicit dependency. reg-07/reg-08 now throw when nothing is perturbable, routing to inconclusive rather than a silent pass.

The inconclusive footnote splits the old `fault_never_fired` into `fault_trigger_not_reached` (agent never reached the tool the fault targets, `failureReason()` null) and `fault_rejected_by_merchant` (fault attempted, `failureReason()` non-null). Perturbations have no failure seam so they always map to trigger-not-reached. The distinction rests on the interferer only setting `failureReason` when `apply()` throws after the trigger tool succeeded.

The hazard-dodge fix adds `target_not_exercised`, scoped to `driver === "agent"`, for journeys that completed clean without their target invariant ever firing on a hazard. It reclassifies them to inconclusive and excludes them from `countDecided`, so a suite of hazard-dodging live journeys cannot report READY. Deterministic reproductions force the hazard and are untouched by the driver scope.

### Money attributed once per order via MAX-per-group

`sumMoneyAtRiskByOrder` keys each violation on `intentId || quoteId || id` and keeps the maximum `moneyAtRiskMinor` per key, then sums the per-key maxima. MAX is the defensible reducer: if two rules on one order ever carried divergent amounts, the larger silently wins with no guard or log — acceptable, but a divergence would go unnoticed. The same function feeds both the per-journey `moneyAtRiskMinor` and the audit-log `money_at_risk`, so the report and the audit trail cannot disagree, and the suite-level prevented/not-prevented split reduces the already-deduped figure (a test pins the two halves summing back to the total for both mutation sets).

The grouping key is where the dedup can be incomplete. `Violation.intentId` is typed non-nullable but the doc comment anticipates an empty value; the `||` chain then falls to `quoteId` and finally to the content-derived `id`. A money-bearing violation with no intent keys on its own unique id and counts once per distinct content, so two intent-less violations on the *same* order would not be deduped. Every fired money case in the live preflight run carried an intentId, so the edge is theoretical, but it is the one gap in the rule. No float math is introduced; all arithmetic stays in integer minor units.

Confirmed live over the preflight SSE route: `reg-04-expired-quote` fires INV-INVENTORY and INV-QUOTE-EXPIRY on one order and reports `moneyAtRisk: 1399`, not the doubled 2798. The README/demo money figures dropped accordingly (₹16,224.18 → ₹13,401.72 vulnerable, ₹12,607.00 → ₹9,809.00 fixed), and `claims.test.ts` pins those strings to a real run so the table cannot drift.

### Perturbation follows the buyer, with an implicit ordering dependency for the fixed suite

`contestedProduct` now scans the most-recent quote's line items and returns the first that still exists in state, falling back to the named product only when the quote yields nothing. This is the substantive correctness fix — against a mapped merchant, a live agent buying something other than arabica previously had the fault applied to a shelf it never reserved, so the target invariant evaluated a benign cart, never fired, and the journey reported a clean pass. The new `perturbation-target.test.ts` buys a ceramic mug, asserts the fault lands on the mug, and asserts INV-INVENTORY fires and the disposition is not `passed` — it exercises the real `contestedProduct` and `runSuite`, so it bites if the name-first order returns.

The caveat is how the deterministic reproductions stay byte-identical. reg-07/reg-08 no longer name arabica directly; they rely on the quote scan resolving to arabica because the scripted HAMPER bundle lists `p-coffee-arabica` first *and* `create_quote` preserves that ordering into `lineItems`. The live preflight run confirms this holds today (reg-07 reprices arabica ₹599→₹649, reg-08 stocks out arabica). But nothing asserts the deterministic perturbation still lands on arabica, so a future change to quote line ordering would silently move the fault to a different product and the reproduction would drift without a test failing. Asserting the chosen product in a deterministic test, or scoping the name-first preference to `driver === "deterministic"`, would make the guarantee explicit rather than incidental.

reg-07/reg-08 now throw when `contestedProduct` returns null, routing the journey to inconclusive instead of silently no-opping into a false pass.

### Four-cause inconclusive split keyed on the interferer's failure seam

The old `fault_never_fired` became `fault_trigger_not_reached` and `fault_rejected_by_merchant`, distinguished by `interferer.failureReason()`. The interferer only sets a failure reason when `apply()` throws *after* the trigger tool succeeded (`result.ok && name === afterTool`); if the agent never reaches the trigger, `apply` never runs and `failureReason()` stays null. So non-null means "attempted and refused" and null means "never attempted". Perturbations have no failure seam, so `perturbationMissed` unconditionally maps to trigger-not-reached, which matches reality since a perturbation that never applied means its trigger was not reached.

One imprecision: the reg-07/reg-08 "no product in this buyer's order could be perturbed" throw fires *after* the trigger, so it sets `failureReason` and the journey reads as `fault_rejected_by_merchant` ("could not be applied to this merchant"). The literal cause there is an empty or unmatched order, not a merchant that refused perturbation. The bucket is defensible from the harness's view but the wording could mislead if this path becomes common; a distinct message would read truer.

`describeInconclusive` names all four causes and is the single shared source the pages and SSE routes render, so adding causes propagates without per-surface edits.

### target_not_exercised reclassification, scoped to agent journeys

A live twin carries a `targetsInvariant` but lets the model pick the bundle; when the agent declines the hazard the target rule runs on a benign cart, lands in `exercisedInvariants` but never `firedInvariants`, and the journey completes clean. The fix computes `targetNotExercised` only when the driver is `agent`, a target exists, it was not withheld, it did not fire, the outcome completed, the merchant did not self-reject, and there are no defects. That guard set is tight: it only reclassifies what would otherwise read as a clean pass, leaving abandoned journeys as `agent_stopped` and any journey with a defect or escalation under its own disposition. The reclassified journey is excluded from `countDecided`, so a suite of hazard-dodging journeys cannot manufacture READY on coverage of nothing.

The `driver === "agent"` scope is what protects the deterministic suite: a reproduction forces the hazard, so its target always fires and the condition is never reached for `driver === "deterministic"`. The tests confirm both directions — a hazard-dodging agent journey becomes inconclusive with `decidedJourneys` 0 and readiness INCONCLUSIVE, while a deterministic reproduction that forces the hazard stays a real finding. An agent journey that *does* present its hazard fires the target and fails the `!firedHere.has(...)` check, so a legitimate pass is not reclassified.

### Test coverage

Each fix exercises the changed path against `runSuite`, not a static assertion: the money test reads reg-04's deduped figure from a real vulnerable run; the perturbation test buys a non-arabica product and asserts the fault reaches it; the inconclusive tests assert each of the four causes and the footnote wording; the target_not_exercised tests assert the reclassification, the `decidedJourneys`/readiness exclusion, and the deterministic-untouched case. The orchestrator independently confirmed the FEAT-005 test bites (revert → 3 fails, restore → 22 pass).

Not tested: no assertion pins the deterministic perturbation to arabica specifically (see the ordering-dependency concern), and the mapped-merchant SSE run's full completion was not exercised end-to-end here.
